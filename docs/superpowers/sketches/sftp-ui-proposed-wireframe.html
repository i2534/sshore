← 错位 132px →

两条红虚线之间 132px 的错位＝过滤框的宽度（实测 125~132px）。列表里「修改时间」的值（x 341–450）正上方是表头行的过滤框（x 320–451），所以你点时间列想排序时，命中的是 input，@click="sortBy('modTime')" 收不到事件。

根因（三条，都能落到代码）
  1. 表头行与列表行各自独立布局：表头多了个过滤框（132px）→ 表头的「大小/修改时间」整体左移 132px。
    代码：.columns 与 .list li 各写一套 flex/宽度，没有一个共享的列定义。
  2. 过滤框实际宽 132px 而不是 CSS 里写的 110px：项目没有全局 box-sizing: border-box，110 + padding(20) + border(2) = 132。
  3. 于是「修改时间」的表头标签被挤到左、过滤框占据了列表时间值所在的正上方——排序按钮的命中区被 input 覆盖。
修法：表头行与列表行共用同一套列轨道（grid），过滤框只占第 4 条轨道 → 表头与列值永远对齐，三个列头永远可点。

根因：全局只统一了 padding，没有统一 height / line-height / box-sizing；各组件又各自覆盖 font-size（fs-11/12/13，工具条还继承 body 的 16px）。Chromium/WebView2 里 <input> 用 line-height: normal、<button> 用字体行盒，两者算出来的高度天然不同 → 同一屏出现 34 / 29 / ≈17 三种高度，同一行内（面板头）也不齐。
修法：定义 --ctl-h: 28px，全局 button,input,select { box-sizing:border-box; height:var(--ctl-h); line-height:1 }，并把 .curpath 的 padding 归到同一套；同一行内所有控件一律 28px（工具条从 34px 收到 28px，面板头 29px 收到 28px）。
